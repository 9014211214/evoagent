# Code of Conduct

## Expected behavior

Participants should:

- communicate respectfully and focus criticism on ideas, evidence, and code;
- state uncertainty and limitations honestly;
- protect private, confidential, and security-sensitive information;
- credit upstream authors, research, data, and software accurately;
- avoid overstating benchmark, safety, training, or deployment results;
- help maintain a technically rigorous and welcoming environment.

## Unacceptable behavior

The following are not acceptable:

- harassment, discrimination, threats, or personal attacks;
- publishing another person's private information;
- submitting stolen, confidential, or improperly licensed material;
- concealing copied code or model/data provenance;
- intentionally introducing secrets, poisoned evidence, malicious Skills, unsafe Tool authority, or misleading evaluations;
- fabricating test, benchmark, training, or deployment results;
- using project discussions to solicit unsafe access to systems or data.

## Enforcement

Repository maintainers may edit, reject, close, or remove contributions and participation that violate this policy. Security-sensitive incidents should be reported privately under `SECURITY.md`, not debated in a public thread.

Enforcement decisions should be documented proportionately, protect affected people, and distinguish good-faith mistakes from repeated or malicious conduct.

## Scope

This policy applies to repository code, issues, pull requests, reviews, discussions, demonstrations, benchmark submissions, and other project spaces controlled by the maintainers.
